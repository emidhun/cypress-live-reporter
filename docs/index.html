01 Quickstart

Three edits, then run as usual

The plugin auto-detects its sink and turns every feature on by default. Point it at a database and run npx cypress run — events start streaming.

1

Wire the Node plugin cypress.config.js

setupNodeEvents(on, config) {
  // streams run/spec/test events + failure evidence
  return require('./tools/cypress-live-reporter/plugin')
    .livePlugin(on, config);
}
2

Wire the browser side cypress/support/e2e.js

require('../../tools/cypress-live-reporter/support');
3

Point it at a sink cypress.env.json

{ "CLR_DB": "postgres://user:pass@host:5432/db" }

Postgres mode (npm i -D pg, then apply schema.sql once). Prefer a webhook? Set CLR_WEBHOOK instead. In CI, use CYPRESS_CLR_DB as an env var.

02 Configuration

One surface: the Cypress env

Everything is set in one place — cypress.env.json, the env block in cypress.config.js, or CYPRESS_* variables in CI (highest precedence). Everything is on by default; you only set keys to point at a sink or turn things off.

▲

CI provenance is automatic. Branch, commit, PR, build URL, and actor are read from the runner's own OS env (GITHUB_*, CI_*) — you never set them. Just remember: plugin config in CI must be CYPRESS_-prefixed, so CYPRESS_CLR_DB sets CLR_DB.

03 The run & project model

One id to identify, one to group

A run is identified by its runId. Set a projectId and every run rolls up under a readable project — queryable as the clr_run_project view or the project_id column on clr_runs.

runId · identity

Unique per run

A fresh UUID each cypress run. Share one CLR_RUN_ID across parallel machines to merge shards into a single run.

projectId · grouping

Shared across runs

A free-form label like todos-web. Stamped on every event, so the mapping holds even with lifecycle events off.

04 The event stream

What a run emits, in order

Every event shares one envelope — runId, seq, ts, type (plus projectId when set). The Node side assigns seq for browser and Node events alike, so (run_id, seq) is a true total order.

before:run
run:start
Specs, browser, Cypress version, and CI metadata.
before:spec
spec:start · spec:tests
The spec begins; its full test roster is announced up front.
per it-block
test:start
Flushed immediately — the live "running" signal.
on failure
artifact:dom · screenshot · commands · console
Failure evidence: serialized DOM, screenshot, the last N commands and console lines.
per attempt
test:attempt:end
State, duration, whether it will retry, and the error.
after:spec
spec:end · artifact:stdout
Per-spec stats; terminal output on failing specs.
after:run
run:end
Final status and totals — then one bounded flush.
